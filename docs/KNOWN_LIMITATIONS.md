# Dream 语言已知限制

## 位置信息不准确

**问题**：编译器错误消息中的行号和列号始终显示为 `line 0, column 0`。

**原因**：Parser 当前没有集成 Menhir 的位置跟踪功能。所有 AST 节点的位置都硬编码为 `{line = 0; column = 0}`。

**影响**：
- 所有编译错误都显示在 line 0, column 0
- 用户需要根据错误消息的其他信息定位问题

**缓解措施**：
- 穷尽性检查错误包含分支编号：`Pattern 'Some' is unreachable (branch #3 in the match expression)`
- 类型错误包含变量名和上下文信息
- 建议使用小的测试文件逐步开发

**修复计划**：
这需要对 parser.mly 进行系统性重构：
1. 使用 Menhir 的 `$startpos` 和 `$endpos` 语义值
2. 在所有语法规则中传递位置信息
3. 更新所有 AST 节点构造

预计工作量：中到大（需要修改 200+ 处 AST 节点构造）

## 模式匹配穷尽性检查的限制

**限制**：
1. 用户自定义枚举的穷尽性检查尚未实现
   - 当前仅支持内置的 Option 和 Result
   - `get_enum_variants` 函数需要从环境中查找用户定义的枚举

2. 列表模式的穷尽性检查简化处理
   - 列表模式当前被视为通配符 (PAny)
   - 无法检测缺失的空列表 `[]` 或非空列表 `[x, ...]` 情况

**示例**：
```dream
# 当前无法检测穷尽性
enum Color:
    Red
    Green
    Blue

match color:
    Color.Red:
        print(1)
    # 编译器不会警告缺少 Green 和 Blue
```

**修复计划**：
1. 在 `get_enum_variants` 中添加环境查找逻辑
2. 增强列表模式的表示和检查

## 其他限制

### 列表推导式
- 返回固定最大容量的数组
- 实际长度信息在编译时丢失

### 类型推断
- 函数参数默认推断为 `int`
- 数组参数需要显式类型注解

### 错误恢复
- 某些情况下编译器在遇到错误后继续编译
- 可能导致误导性的后续错误
